## Verified boundaries

- **Authorization and source identity:** the endpoint's identity dependency checks server-owned project membership, then resolves the document only within that project before invoking the original-file reader (`api.py:162–172`). It accepts only a validated lowercase SHA-256 object key and a PDF document name. The renderer checks the actual bytes against that hash and the PDF signature before native rendering. Missing objects, wrong types, corruption and changed hashes produce explicit errors; this path has no extracted-text fallback.
- **Read-only resource bounds:** the original has a 15 MiB stat/read limit. API validation bounds page number to 1–10000 and requested dimension to 256–2400; the renderer additionally checks the actual PDF page count. Finite positive page geometry determines scale before allocation, with rounding allowance under the four-million-pixel cap and post-render checks. The image, bitmap, page and document close on success or failure. PNG responses carry private/no-store, nosniff, original hash/page and actual raster dimension headers. Tests confirm unchanged original bytes and package state.
- **Native PDF access:** API `.pdf` ingestion and preview share the same process lock (`api.py:56–59`, `page_preview.py:20–27`). The lock covers the entire parser operation, including its native-text supplement, and the complete rendering/handle-close lifetime. A preview encountering an active parser or another preview returns an actionable 503 retry message before entering PDFium. Upload parsing runs in the thread pool; failure releases the lock and does not save a document. This is process-local serialization, as documented.
- **Browser lifecycle:** source selection does not request a preview. An explicit action fetches only the requested page with the current bearer token. The component requires a PNG response, exposes errors/retry, and offers fit-width/2× viewing and full-image opening. Page switches remount the component; changes to source context, inspector visibility or token clear the preview. Effect cleanup aborts the fetch and revokes its blob URL; disposed responses cannot create a late image. No source text or generated placeholder is rendered as an original page.
