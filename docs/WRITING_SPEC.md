# Writing requirements

These rules apply to the technical report, demo narration, README and presentation copy.

## Technical prose

Use Simplified Technical English as an editing target. Preserve engineering terms, identifiers, units and measured results.

- Limit instructions and prose bullets to 20 words.
- Limit descriptive sentences to 25 words.
- State one claim per sentence.
- Use active voice with an explicit actor when it changes the meaning.
- Prefer plain verbs: is, has, uses, cuts, builds, checks, stores, rejects.
- Do not claim formal ASD-STE100 conformance or ISO certification.

## Prohibited wording

Do not use correlative rhetorical framing, negative parallelism, throat-clearing openers, or trailing participial commentary.

Remove phrases such as "not only ... but also", "whether X or Y", "both X and Y", "not just", "more than just", "at its core" and "it is important to note".

Do not end a sentence with comma-plus-ing commentary. Replace generic adjective triplets with a measured value or mechanism.

## Slides

Every headline contains an action verb and a result. Use at most 10 words.

Every bullet uses this form: **Component or mechanism**: Concrete action or metric.

Use at most 12 words per bullet and at most 4 bullets per slide. Tables and diagrams must add specific technical content.

## Evidence

Preserve source URLs, code identifiers, dates, numbers, raw model results and uncertainty. Describe planned work as planned work.

Humanizer edits prose only. The user's explicit slide bullet format takes priority over Humanizer's general advice against labeled bullets.
